# InstaScaler — audyt, spolszczenie i marka DELTA240MVT

Data: 8 września 2026. Branch: `baza080926-polish`.

## Zakres i wynik

Przejrzano granice Web/Core/Jobs, trasy API, uwierzytelnianie, konta i OAuth,
kampanie, import, skrzynkę, raportowanie, śledzenie kliknięć, dostarczanie
wiadomości, rezerwacje, kolejkę i wszystkie zadania cykliczne. Potwierdzone
błędy naprawiono i objęto regresjami. Panel i strony publiczne mają polskie
teksty oraz typografię i kolory głównej marki.

To audyt kodu i wykonania lokalnego. Testy granic Meta/Neon/Cloudflare korzystają
z kontrolowanych odpowiedzi, a test agregacji SQL uruchamia rzeczywisty silnik
PostgreSQL w PGlite. Nie należy interpretować tych wyników jako potwierdzenia
działania konkretnej instalacji produkcyjnej.

## Najważniejsze naprawy

1. **Panel pomijał poprawne dane Core.** Oczekiwał pola `success`, podczas gdy
   API zwraca `{ data }`. Odczyty korzystają z rzeczywistego kontraktu;
   nieudane zapisy nie udają sukcesu i nie usuwają szkicu użytkownika.
2. **Potwierdzenie webhooka wyprzedzało trwały zapis.** Core potwierdza dopiero
   po R2, a awaria zwraca 503. Przyjęcie zdarzenia i budżet mają wspólną
   transakcję; powtórki i odzyskiwanie nie obchodzą limitów.
3. **Dostarczanie miało luki w ponowieniach.** Naprawiono współbieżne przejęcia,
   pauzę konta, obsługę postbacków, sprzątanie po dostarczeniu, limiter godzinowy,
   retencję oraz wznowienie workflow. Follow-up ma trwały dziennik R2 i zachowuje
   odbiorcę oraz pierwotny termin po awarii publikowania Queue.
4. **Ręczne odpowiedzi omijały wspólną ścieżkę wysyłki.** Core wywołuje prywatny
   `JOBS_API` → `ManualMessages`; Jobs sprawdza konto i rezerwuje limiter przed
   Meta. Wygasły token zatrzymuje konto i zwraca bezpieczny komunikat.
5. **Zapis kampanii kasował istniejące śledzone linki.** Edycja zachowuje slugi,
   tożsamość linków i historię kliknięć. Duplikowanie zachowuje opcje wysyłki,
   ale tworzy wstrzymaną kampanię bez przenoszenia dostępu do raportu.
6. **Walidacja i odczyty były niespójne.** PATCH sprawdza wynikową konfigurację,
   import waliduje wszystkie wiersze, raporty agregują SQL zamiast pobierać
   każdy log, a historia obserwujących obejmuje ostatnie 365 punktów.
7. **Logowanie miało przypadki brzegowe.** Weryfikacja Origin poprzedza
   przepisywanie nagłówka w proxy. Nieprawidłowy cookie nie blokuje logowania;
   zewnętrzny lub wielokrotny `callbackUrl` jest bezpiecznie odrzucany.
8. **Brakowało subskrypcji kliknięć wiadomości.** Dodano `messaging_postbacks`
   w obu klientach Meta. Źródło i instrukcja aktualizacji: [audyt Core](2026-09-08-core.md).

## Spolszczenie i styl

- Polski interfejs logowania, pulpitu, przeglądu, kampanii i edytora, importu,
  skrzynki, ustawień, dziennika, diagnostyki, raportu i stron publicznych.
- Polskie błędy, etykiety dostępności, potwierdzenia, przykłady, osiem szablonów,
  domyślne wiadomości, daty i liczby. Dokument HTML ma `lang="pl"`.
- Nazwy pól API/CSV, kody diagnostyczne i teksty zapisane wcześniej przez
  użytkownika pozostają danymi, bez automatycznego tłumaczenia.
- Inter i IBM Plex Mono ładowane lokalnie, z licencjami OFL. Zweryfikowano
  komplet znaków `ąćęłńóśźżĄĆĘŁŃÓŚŹŻ` w każdym wynikowym pliku fontu.

  tła `#F8F7F3` i `#FFFEFA`; ciemny tekst na jasnym akcencie, wyraźny fokus,

### Korekta odstępów po ocenie użytkownika

Ponownie porównano rzeczywiste reguły `theme.css` portalu: zwykły tekst nie ma
ujemnego odstępu liter, a jego interlinia wynosi 1,55. W nowszym wariancie
strony nagłówek hero ma interlinię 1,02. W InstaScalerze usunięto globalne
`letter-spacing: -0.008em`. Tytuły panelu mają teraz wagę 800, odstęp -0,03em
i interlinię 1,18; nagłówek logowania wagę 800, odstęp -0,035em i interlinię
1,05. Zapewnia to więcej miejsca między literami i wierszami w mniejszym
interfejsie panelu. Fonty Inter i IBM Plex Mono pozostają bez zmian.

Po korekcie `npm run build` i `npm run lint` zakończyły się kodem 0.
Przeglądarkowy zestaw logowania i głównych widoków przeszedł na desktopie
i telefonie: 4 testy, kod 0. Obejrzano nowe zrzuty ekranu; nagłówki nie są
ucięte, a główne widoki zachowują szerokość ekranu.

Obejrzano zrzuty pulpitu i logowania na desktopie i telefonie, sprawdzono

Zrzuty są w ignorowanym `test-results/`. Buildy, logi, wygenerowany Prisma
i wyniki przeglądarkowe nie są dodane do indeksu Git. Zastane artefakty
użytkownika pozostawiono bez zmian.

Wcześniejszy test SQL przekroczył 20 sekund podczas równoległego builda.
Zwiększono wyłącznie limit czasu startu silnika PGlite do 60 sekund; asercje
pozostały bez zmian. Osobny przebieg oraz późniejszy pełny zestaw przeszły.
Początkowe niepowodzenia E2E związane z selektorami zostały skorygowane na
rzeczywiste polskie nazwy kontrolek. Testy pracują na buildzie produkcyjnym,
aby nie zależeć od kompilowania tras przez serwer deweloperski.

Pierwszy równoległy przebieg `npm run lint` trafił na usuwany przez Playwright
katalog `test-results` i zakończył się ENOENT. Wyniki Playwright wyłączono
z zakresu ESLint; końcowy lint przeszedł. Pozostają ostrzeżenia narzędzi:
OpenNext o ograniczonym wsparciu Windows, Next o konwencji `middleware`
oraz Vite o przyszłym loaderze konfiguracji. Nie blokują obecnych buildów i testów.

## Granice i test po wdrożeniu

Brak zmiennych `E2E_*` dla docelowego środowiska uniemożliwia uruchomienie
bramkowanego `npm run test:e2e`. Lokalne scenariusze przechwytują `/api/*`;
nie wykonują prawdziwego OAuth, wysyłek do użytkowników ani operacji na
produkcyjnej bazie. Nie weryfikują rzeczywistej kolejki, alarmów Durable Objects,
sieci Cloudflare, przyznanych uprawnień Meta ani wdrożonego bindingu RPC.

Po wdrożeniu Jobs → Core → Web należy ponownie połączyć istniejące konto,
aby odświeżyć subskrypcję, i wykonać scenariusz konta testowego opisany
w `INSTRUKCJA.md`: komentarz, otwarcie, przycisk, follow-gate, link, follow-up,
ręczna odpowiedź i powtórzony webhook.

Pozostają jawne ograniczenia istniejącej architektury:

- Meta i Neon nie stanowią jednej transakcji. Awaria po zaakceptowaniu wysyłki,
  przed zapisem wyniku, może pozostawić niejednoznaczne `PROCESSING`. Przed
  ręczną interwencją trzeba sprawdzić rzeczywistą rozmowę.
- Import ma osobne zapisy po wspólnej walidacji; awaria infrastruktury może
  pozostawić częściowy wynik. Szczegóły ponawiania podaje audyt Core.
- Jawne usunięcie kampanii/linku usuwa powiązane dane zgodnie z istniejącą
  relacją Cascade. Zachowanie historii dotyczy edycji.
- Lista kampanii nadal zwraca komplet metadanych; agregacje eliminują wzrost
  odpowiedzi wraz z liczbą wiadomości, bez zmiany API na paginowane.

Szczegóły domen: [Core](2026-09-08-core.md), [dostarczanie](2026-09-08-delivery.md),

istniejących Workerów produkcyjnych z oznaczeniem wersji `--tag main`.
