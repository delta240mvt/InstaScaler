# Audyt Core — 2026-09-08

Zakres: uwierzytelnianie i sesje administratora, kontrola Origin, OAuth i konta Instagram, kampanie i import, webhook, ręczna wysyłka z inboxu, raporty publiczne, statystyki, przekierowania i diagnostyka. Przeczytano schemat Prisma, trasy i bezpośrednich odbiorców zmienianych kontraktów. Bez migracji bazy, wdrożeń, commitów, pusha ani operacji na kontach produkcyjnych.

## Potwierdzone i naprawione

- **Utrata webhooków przy awarii R2:** odpowiedź 200 wyprzedzała trwały zapis. Core zapisuje teraz dziennik przed potwierdzeniem; awaria zapisu zwraca bezpieczne 503 i identyfikator żądania. Budżet i publikacja Queue pozostają w `waitUntil`, bez wysyłania wiadomości w odpowiedzi webhooka.
- **Powtórne rozliczanie/bypass przy odzyskiwaniu:** webhook korzysta ze wspólnej funkcji `admitInboundEvent`, która atomowo rezerwuje budżet i zapisuje `ProcessedEvent.RECEIVED`. Publikowane są wyłącznie nowo przyjęte zdarzenia. Część Jobs/recovery została skoordynowana z audytem dostarczania.
- **Niepoprawne elementy webhooka:** puste wpisy nie przerywają przetwarzania pozostałych. Zastępczy identyfikator postbacka ma stały rozmiar SHA-256, zawiera konto i czas komunikatu, a nie potencjalnie bardzo długi payload przycisku.
- **Brak subskrypcji kliknięć przycisków:** obaj klienci Meta subskrybują `messaging_postbacks` obok komentarzy i wiadomości. Wymaganie potwierdza [oficjalna kolekcja Instagram API firmy Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-af579d08-121e-4897-8f45-5fd41ace49df). Już połączone konta wymagają ponownego połączenia/subskrypcji po wdrożeniu.
- **Utrata linków i kliknięć przy zapisie kampanii:** PATCH usuwał wszystkie linki i tworzył nowe. Zapis aktualizuje istniejące wiersze, zachowując slugi i historię kliknięć; częściowa zmiana jednego linku zachowuje drugi. Kolejność linków w odczycie jest zgodna z dostarczaniem wiadomości.
- **Niespójne PATCH i import:** walidowana jest konfiguracja kampanii po połączeniu poprawki z bieżącymi wartościami. Import waliduje wszystkie wiersze przed pierwszym zapisem, rozpoznaje duplikaty w obrębie konta i raportuje także utworzone kampanie bez konkretnego posta. Linki śledzone przyjmują wyłącznie HTTP/HTTPS.
- **Błędne odpowiedzi i wycieki diagnostyczne:** `null`, błędne typy i niepoprawny JSON mają odpowiedzi klienta zamiast niezamierzonych 500. Awaria bazy podczas tworzenia kampanii nie jest już udawanym błędem walidacji 400. Logi wyjątków Core/webhooka i niedostępnych statystyk Meta nie zapisują surowych komunikatów mogących zawierać tokeny.
- **Przekierowanie logowania poza aplikację:** odrzucane są backslashe oraz warianty, które przeglądarka normalizuje do innego originu.
- **Ręczna wysyłka poza limiterem:** Core waliduje treść i odbiorcę, a następnie wywołuje `JOBS_API.sendManualMessage`. Jobs odpowiada za odszyfrowanie tokenu, limit konta i wywołanie Meta. Binding i implementacja Jobs należą do zmian koordynatora.
- **Zbyt duże odczyty statystyk:** listy kampanii i publiczne raporty agregują wyniki w PostgreSQL, z pięcioma najczęstszymi słowami na kampanię, zamiast pobierać każdy DmLog. Raport publiczny udostępnia `analytics`, bez indywidualnych wierszy dostarczenia. Kontakty dashboardu są liczone przez SQL COUNT DISTINCT.
- **Nieaktualne odczyty:** historia obserwujących zwraca najnowsze 365 punktów chronologicznie. Nieprawidłowy filtr statusu dziennika jest odrzucany przed zapytaniem. `SKIPPED` jest poprawnie uwzględniany w funkcji podsumowującej. Dni tygodnia dashboardu są po polsku.
- **Równoległe łączenie kont:** transakcja weryfikująca limit pięciu kont korzysta z izolacji Serializable.
- **Ponowienie FOLLOW_UP:** diagnostyka odczytuje pełne zachowane zadanie z R2 i sprawdza jego typ oraz zgodność identyfikatora i konta przed publikacją.

## Granice sprawdzenia

- Nie wykonywano rzeczywistego OAuth, wysyłki Meta ani mutacji produkcyjnych; zgodność uprawnień i stan subskrypcji istniejących kont wymagają testu po wdrożeniu.
- Jawne usunięcie linku lub kampanii nadal usuwa powiązane dane zgodnie z istniejącymi relacjami Cascade. Zachowanie historii dotyczy edycji istniejących linków, nie ich usuwania.
- Import wykonuje osobne zapisy po wspólnej walidacji. Awaria infrastruktury w środku importu może pozostawić część utworzonych kampanii; ponowienie pomija już istniejące posty danego konta.
- Konflikt równoległych transakcji łączenia kont może wymagać ponowienia połączenia; nie może przekroczyć limitu pięciu kont.
- Lista kampanii nadal zwraca komplet metadanych kampanii. Usunięto wzrost wielkości odpowiedzi wraz z liczbą wiadomości, bez wprowadzania nowego kontraktu paginacji kampanii.
